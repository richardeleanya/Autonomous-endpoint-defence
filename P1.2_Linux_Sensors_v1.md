## 1. Collection sources

| Source | Events | Preference |
|---|---|---|
| eBPF CO-RE (tracepoints/kprobes) | process exec, file open/read/write, network connect, credential changes | Primary |
| fanotify | file access events | Fallback for file events |
| audit (auditd rules) | execve, syscalls | Fallback when BPF unavailable |
| cgroup/namespace inspection | container context | Always (user-mode) |

All eBPF programs are verifier-safe. No custom kernel module without approved ADR.

---

## 2. Support matrix

| Distribution | Versions | Kernel range | Capability |
|---|---|---|---|
| Ubuntu LTS | 20.04, 22.04, 24.04 | 5.4+ / 5.15+ / 6.8+ | Full eBPF CO-RE |
| RHEL family | RHEL 8, 9 (and derivatives) | 4.18+ / 5.14+ | Full eBPF CO-RE where available; fanotify/audit fallback on older kernels |

**Unsupported kernels:** Degrade to fanotify+audit, report `capability=DEGRADED, reason=NO_BPF` (never silent). Telemetry continues at reduced fidelity.

---

## 3. Container and Kubernetes awareness

- Every event includes `container_id` and `cgroup_path` when running in a container.
- Namespace IDs (pid/mnt/net/user) captured for correlation.
- Container runtime identity (containerd/docker) resolved in user mode.
- Kubernetes node context: pod name, namespace, labels (when running as DaemonSet with RBAC) captured where available.

---

## 4. Hardening

- **systemd sandboxing:** `ProtectSystem=strict`, `ProtectHome=true`, `NoNewPrivileges=true`, `PrivateTmp=true`, `CapabilityBoundingSet` minimal.
- **SELinux/AppArmor profiles:** Confining profiles for agent binaries; shipped per distribution.
- **Immutable binaries:** Read-only filesystem mounts for agent binaries; integrity check at startup.
- **Integrity checks:** Hash verification of binaries/config; emit tamper event on mismatch.

---

## 5. Resource budgets and load shedding (TARGETs)

| Resource | Budget (TARGET/HYPOTHESIS) | Measurement |
|---|---|---|
| CPU | <= 2% average | perf counters, 24 h soak |
| Memory | <= 256 MiB RSS | RSS sampling |
| Event throughput | >= 100,000 events/s sustained | Synthetic replay |
| Load shedding | Drop lowest-priority telemetry under pressure; account in LossReport | Flood test |

Load shedding never drops security-critical events without accounting.

---

## 6. Canonical event emission

- Same canonical schemas as P0.5 (Observation, ProcessEvent, etc.) with `container_id`, `cgroup_path`, `namespace_ids`.
- Back-pressure and loss accounting identical to P1.1.
- Fail-open: collection failure does not crash host; telemetry continues at degraded fidelity with reported capability.
