## 1. Observation gossip

- **Signed, advisory-only:** Every peer message is an envelope (P0.3) with signature; observations are advisory, never authoritative.
- **Bounded fan-out:** Configurable max peers per gossip round.
- **Size limits:** Max message size enforced (P0.5 rate/size limits).
- **Anti-flood:** Rate limiting per peer; excess dropped with accounting.
- **Replay windows:** Nonce + issued_at/expiry (P0.3 §4).

---

## 2. Corroboration engine

- **Distinct devices only:** Count only distinct attested devices (P0.3 §5.1). Duplicate device_id collapsed.
- **Reputation weighting:** Weight by trust level (L3>L2>L1) and history.
- **Collusion limits:** Require k distinct devices from >=2 independent trust paths; flag clusters (subnet, enrolment batch, timing).

---

## 3. Partition, healing, churn, clock skew

- **Partition:** Enter local mode; peer-dependent T2 denied; T0 continues.
- **Healing:** Re-sync; no duplicate actions (idempotency by action_id).
- **Churn:** Handle peer join/leave gracefully; attestation re-verified.
- **Clock skew:** Skew bound enforced; messages outside bound dropped (R-CLOCK-SKEW).

---

## 4. Simulator

- **Scale:** 1,000–10,000 simulated nodes.
- **Adversary tests:** Compromised/colluding nodes, flooding, spoofing.
- **Ground truth:** Real-VM lab runs for validation.

---

## 5. No peer-originated remediation (MESH-005)

- Peer input only changes confidence or corroboration counts.
- No remote command channel between peers.
- Action authority comes only from policy decision + valid token (P0.2 ADR-001).

---

## 6. Metrics

- Gossip rate, fan-out, message size, flood drops, replay drops, corroboration counts, distinct device counts, cluster flags, partition events, healing time — all exposed to control plane.
