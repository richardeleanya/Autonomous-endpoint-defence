## 1. Implementation design

- **Language:** Memory-safe (ADR-003). No AI, no network, no I/O in evaluator.
- **Parser:** Recursive-descent or generated parser with bounded depth (max 8). Produces AST.
- **Evaluator:** Pure function `decision = f(proposal, context, policy)`. Deny-overrides semantics (P0.4 §1.3). Bounded evaluation (max 256 rules, 1024 iterations, 10 ms TARGET).
- **Signed-bundle loader:** Verifies signature (P0.3), tenant match, version monotonicity, expiry; rejects invalid bundles (R11).
- **Simulator:** Replays recorded proposals against a policy bundle; outputs decisions with rule IDs and reason codes.

---

## 2. Conformance suite

- All 42 POL-T tests (P0.4 §7) plus additional cases for each rule branch.
- Expected output format: `POL-T-xxx PASS decision=... rules=[...] reason=...`.
- Determinism check: same input repeated 10,000 times yields one distinct output hash.

---

## 3. Property-based tests

- For each invariant INV-1..INV-14 (P0.4 §5), generate >=1,000,000 cases (TARGET).
- Record seed for reproducibility.
- Zero violations required.

---

## 4. Fuzzing

- Fuzz targets: parser (malformed policy text), bundle loader (malformed signed bundles), evaluator (boundary inputs).
- Run in CI (smoke) and nightly (deep). Crashes triaged and fixed.

---

## 5. Formal analysis

- Model checking of core state machine (rule evaluation + deny-overrides) where practical.
- Document scope and limitations.

---

## 6. Reproducible builds

- Pinned toolchain, lockfiles; build twice and compare hashes.
- Provenance attached (P0.10).
