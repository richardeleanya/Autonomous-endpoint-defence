## 1. Collection sources (documented interfaces only)

| Source | Events | Interface |
|---|---|---|
| ETW Microsoft-Windows-Kernel-Process | ProcessStart/Stop | ETW consumer (user-mode) |
| ETW Microsoft-Windows-Kernel-File | File create/read/write/delete | ETW consumer |
| File-system minifilter | Create, rename, delete, write | FltMgr (kernel, minimal) |
| Registry callbacks | RegNtPre/Post operations | CmRegisterCallbackEx (kernel, minimal) |
| Windows Filtering Platform (WFP) | Network connect/accept | WFP callout (kernel, minimal) |
| ETW Microsoft-Windows-Kernel-Network | TCP/UDP events | ETW consumer |
| AMSI | Script content (PowerShell, JS, etc.) | AMSI provider (user-mode) |
| ETW Security/Logon | Identity and logon events | ETW consumer |
| WMI/Event Log | Service and system events | User-mode |

No technique disables OS protections. All interfaces are documented public APIs.

---

## 2. Kernel / user-mode split

**Kernel (minimal, signed, reviewed):**
- File-system minifilter: path/operation metadata only; no content capture in kernel.
- Registry callback: key/value metadata; no blocking by default.
- WFP callout: connection metadata (5-tuple, process); no payload capture.
- All kernel components are minimal, isolated, and reviewed by a named specialist (MR13, MR15).

**User-mode service:**
- ETW consumers, AMSI provider, event normalisation, canonical schema emission, bus publishing, resource governor, tamper protection, update client.

**Rationale:** Only what user mode cannot do (kernel callbacks) resides in kernel; everything else runs user-mode to minimise TCB and attack surface (ARC-003, ARC-004).

---

## 3. Canonical event emission

- Events normalised to canonical schemas (P0.5): Observation, ProcessEvent, FileEvent, RegistryEvent, NetworkEvent, IdentityEvent, ScriptEvent.
- Each event includes monotonic timestamp, sequence number, tenant/device context, payload hash.
- **Back-pressure:** Bounded queue; when full, apply drop policy (drop lowest-priority telemetry; never drop security-critical events without accounting).
- **Loss accounting:** Every drop is counted and reported in a `LossReport` event; no silent loss.
- **Fail-open:** If the bus is unavailable, buffer to disk (bounded); if buffer full, drop with accounting. Telemetry never blocks the host.

---

## 4. Tamper protection

- **Service:** Protected service with DACLs; restart on crash via watchdog; service control manager ACLs.
- **Files:** ACLs on agent binaries/config; integrity checks at startup; self-hash verification.
- **Registry keys:** Protected keys (HKLM\Software\...) with ACLs.
- **Processes:** Job objects / process protection (where supported) to prevent termination by non-admin.
- **Configuration:** Signed configuration; reject unsigned changes.
- **Detection of tampering:** Emit tamper events to ledger; alert on unexpected changes.

## 5. Resource governor (TARGETs, to be measured)

| Resource | Budget (TARGET/HYPOTHESIS) | Measurement |
|---|---|---|
| CPU | <= 2% average under mixed load | OS perf counters, 24 h soak |
| Memory | <= 256 MiB RSS | RSS sampling |
| I/O | <= 50 MB/h disk write (TARGET) | I/O counters |
| Event throughput | >= 100,000 events/s sustained (TARGET) | Synthetic replay benchmark |

Governor enforces budgets by dropping lower-priority telemetry and throttling collection; never crashes host.

---

## 7. Fail-safe behaviour

- Sensor fault (crash, hang, exception) is isolated: watchdog restarts the component; kernel minifilter must not crash the host (try/except, safe defaults).
- Telemetry fails open: if collection fails, host continues; loss is accounted.
- Enforcement never starts by accident: P1 has no enforcement path; containment is P2. Kernel components have no T2+ action capability.

---

## 8. Kernel component design note

- **Minifilter:** Altitude registered; pre/post callbacks for create/rename/delete/write; returns FLT_PREOP_SUCCESS_NO_CALLBACK where possible; no blocking in P1.
- **Registry callback:** Pre-notification only; logs metadata; no modification.
- **WFP callout:** Classify at ALE (Application Layer Enforcement) for connect/accept; metadata only.
- **Signing:** Kernel driver signed per Microsoft requirements; Secure Boot compatible.
- **Review:** Every kernel code path reviewed by a named human specialist (MR13, MR15).
